OrgMemory is a self-hosted, governed memory layer for enterprise AI. It turns
uploads and approved connector evidence into versioned, citable knowledge while
preserving source permissions across search, Assistant, API, and MCP delivery.

<Callout title="Current maturity" type="warn">
  OrgMemory is a production-shaped proof of concept. Its architecture, automated
  security checks, deployment pipeline, and rollback path are real; pilot
  readiness still depends on the operational evidence listed under
  [Limitations](/docs/architecture-security/evaluation/limitations).
</Callout>

## The problem

Enterprise AI systems often copy content into an index and lose the context that
made the content trustworthy: which source revision was read, who could read it,
which model created a projection, and which evidence supported an answer.
OrgMemory keeps those facts inside the retrieval boundary.

It is designed for three related jobs:

- preserve source evidence as immutable revisions rather than mutable blobs;
- make authorization part of candidate selection, ranking, graph expansion,
  citations, and Asset delivery;
- package reusable organizational capability as governed releases instead of
  unreviewed prompts or files.

## Scope boundaries

OrgMemory is not a source-of-truth replacement, a public content marketplace, or
an authorization system inferred from email addresses. It does not grant access
because an AI model found a relevant chunk. Source systems remain authoritative
for their content permissions, OpenFGA governs product relationships, and the
canonical ledger decides what may enter a response.
